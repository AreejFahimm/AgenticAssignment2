## 3. Real vs synthetic (every record has a `provenance`)
| Provenance | Meaning |
|---|---|
| `real:<folder>` | a Kaggle job post (PII masked) |
| `real_modified:<job_id>` | a real post we EDITED to plant a scam, injection or duplicate; original id in `planted.base_job` |
| `synthetic:<generator>:<seed>` | generated by us: **3 personas** (24 case studies, ~8 repos, 10 reviews, 150 past proposals each, `data/personas/`), client histories + hidden preferences (inside GigSim-local), conversations |
Composition of the evaluation sets (counts from `build_dev_set.py` output): dev = 188 / 190 / 190 jobs (AI-ML / full-stack / data analyst), of which 175 / 178 / 177 are real posts and 13 / 12 / 13 are planted scams;
held-out = 48 / 46 / 46 (never tuned on); injection set = 48 jobs; 10 duplicates per persona go to the job stream. ~30% of each dev set is deliberately off-domain so that "skip" occurs naturally.

## 4. Labels (SILVER, not human ground truth)
- **bid/skip:** required-skill overlap with the persona ≥ 0.5, budget at or above the persona floor, not a planted scam.
- **scam:** planted scams only; real posts are assumed non-scam (unverified).
- **relevant evidence:** persona case studies/READMEs/code with the highest required-skill overlap (derived from item skill metadata).
- **fair price band:** p25–p75 of market statistics (skill-level if n ≥ 20, else category).
- **past-proposal outcomes:** drawn from the documented rule `outcome_probs` (assumed reply/win rates; not estimated from data).
- **Hand check:** NOT done yet. Hand-label a sample (your 30 judge-calibration items double as this) and report agreement before quoting gold-based numbers as accurate.

## 5. Splits
Held-out slice = hash-based ~20% of the dev pool (`heldout_*.jsonl`); used only for the V8 threshold check. Past-proposal jobs are excluded from dev jobs. The instructor's hidden test set is never committed.

## 6. Limitations (read before trusting a number)
- Gold evidence is defined from the same skill taxonomy that the generators and the preprocessor use: retrieval variants that exploit skill metadata (V6) are partly circular.
- Real posts yield noisy keyword skills (e.g. "excel" for a data-entry job); many real jobs are off-domain for the persona taxonomy.
- Template-generated personas are much cleaner than real portfolios; retrieval numbers are optimistic about real portfolios.
- GigSim-local client behaviour is rule-based; reply rates measure agreement with those rules, not real clients.
- English/US skew, 2024 snapshot, self-reported budgets, scraped-text quality, no outcome data in the Kaggle files used.

## 7. Handling
`data/raw/` and `data/processed/` are git-ignored; only scripts, the small `data/personas/` synthetic corpora, `evals/datasets/` (dev/held-out/injection) and `evals/results/` are committed.
No tokens, live-mode data or hidden test data are stored.
